# Стенд ручных проверок в живом приложении

Четыре скрипта, которыми проверяется то, что не ловится тестами: раскладка,
цвета, поведение при нажатии. Каждый из них написан не сразу — каждый оплачен
отладкой, и правила ниже выведены из настоящих провалов, а не придуманы.

```powershell
powershell -File bench\ui\shot.ps1  C:\путь\снимок.png
powershell -File bench\ui\keys.ps1  "^p" "имя файла" "{ENTER}"
powershell -File bench\ui\click.ps1 314 83
powershell -File bench\ui\click.ps1 592 262 ctrl
powershell -File bench\ui\hover.ps1 200 83
```

Координаты — от левого верхнего угла окна, в той же системе, в которой снят
снимок `shot.ps1`. Приложение должно быть уже запущено.

## Почему они устроены именно так

**Снимок — через `PrintWindow` с флагом `PW_RENDERFULLCONTENT` (`0x2`).**
Передний план из фонового процесса дают не всегда, а `PrintWindow` работает
и с неактивным окном. Без флага содержимое WebView2 в снимок не попадает —
получится пустой прямоугольник.

**Передний план забирается через `AttachThreadInput`, и результат
проверяется.** `SetForegroundWindow` из фонового процесса Windows блокирует;
без проверки нажатия уходят в чужое окно — однажды ушли прямо в проводник.

**Переднего плана мало для клавиатуры.** WebView2 держит содержимое
в дочернем окне, и пока щелчка внутрь не было, фокус остаётся на рамке:
нажатия приходят в приложение и не доходят до вебвью. Поэтому `keys.ps1`
сначала щёлкает в рабочую область.

**Перед щелчком окно прибивается к началу экрана** (`SetWindowPos`). Окно
между вызовами переезжает, и координаты, посчитанные от прошлого положения,
попадают мимо на сотни пикселей — при этом скрипт бодро отчитывается
об успехе.

**`SendKeys` считает служебными `+ ^ % ~ ( ) { } [ ]`.** Их надо оборачивать
в фигурные скобки, иначе регулярное выражение доедет искалеченным.

## Главное правило

Целиться надо по проверке, а не по вере: щёлкнуть, снять экран, убедиться,
что попал. И если что-то не сработало — сначала проверить стенд на команде,
которая точно работала раньше (`Ctrl+N`), а уже потом чинить приложение.
Трижды за этап 2 виноват оказывался стенд.
