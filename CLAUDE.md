# ZeroNote — правила проекта

Краткий свод для рабочих сессий. Подробности — в [DESIGN.md](DESIGN.md):
журнал решений (раздел 10, Р-001…Р-302), планы и приёмки этапов.
При расхождении между этим файлом и `DESIGN.md` прав `DESIGN.md`.

История этапов здесь не пересказывается — она в приёмках `DESIGN.md`.
Прежняя подробная версия этого файла, с пересказом этапов 1–17, —
`git show 486cfd6:CLAUDE.md`.

## Что это

Десктопный редактор для Windows: скорость развёртывания Notepad++ плюс папки
как проекты и удобства VS Code и Obsidian (Р-114). Один разработчик, работа
по вечерам.
Тестировщики — около 35 друзей-разработчиков. Проект будет опубликован в
открытом доступе.

Формат проекта — **свой** (`zeronote.toml`), а не разбор `.obsidian`; из
хранилища Obsidian переносится один раз пара настроек узким переходником.
Связи между заметками (`[[wikilinks]]`, frontmatter, теги) — свойство
markdown-файлов в проекте, а не «режима Obsidian». Решение Р-022.

## Границы первого круга

Только Windows 10/11, только локальная файловая система.

**Вне области — не реализовывать, не закладывать, не «на всякий случай»:**
синхронизация и облако, Linux, Android, шифрованные контейнеры, менеджер паролей,
плагинный API, макросы, пользовательские синтаксисы (UDL), LSP и автодополнение,
сравнение файлов, FTP/SFTP, совместное редактирование.

Возникла идея из этого списка — не реализовывать, а добавить строку в `DESIGN.md`,
раздел «Отложено». Linux владелец хочет отдельной работой позже
(2026-09-27) — до неё он остаётся в этом списке.

## Инварианты — нарушать нельзя никогда

1. **Чужие файлы неприкосновенны.** Сохраняются исходная кодировка, тип переноса
   строк, наличие/отсутствие финальной новой строки, содержимое frontmatter.
   Никакого автоформатирования и нормализации без явной команды пользователя.
2. **`.obsidian` только для чтения.** Читать можно. Записывать — нельзя ни при
   каких условиях.
3. **Сохранение атомарное.** Временный файл в той же директории, сброс на диск,
   замена целевого. Права и атрибуты исходного файла сохраняются.
4. **Несохранённые данные не теряются.** Черновики пишутся с задержкой ~2 с после
   последнего изменения. После аварийного завершения восстанавливаются все
   вкладки, включая буферы без файла на диске.
5. **Кодировка — часть модели буфера, а не деталь ввода-вывода.**
6. **Ввод не блокирует отрисовку.** Индексация, обход дерева, поиск по папке —
   в фоне и отменяемы.

Если запрос противоречит инвариантам или границам области — сказать прямо и
предложить альтернативу, не выполнять молча.

## Карта: что легко нарушить

Решения, которые нарушаются не подумав. Подробности и «почему» — в журнале
решений `DESIGN.md` по номеру.

### Файлы и чужие правки

- **Кодировка, переносы, финальная строка — модель буфера** (инв. 1, 5).
  Настройки проекта кодировку подсказывают, а не назначают (Р-050…Р-052);
  отступ определяется по файлу, настройка — только умолчание (Р-106).
- **В папку пользователя не пишется ничего без явной команды** (Р-049);
  `zeronote.toml` — только по кнопке и с переспросом.
- **`.obsidian` — каким его читает Windows** (Р-299): точки и пробелы
  на конце части пути отбрасываются, короткое имя 8.3 и связь ведут туда
  же под другим именем. Сторож один — `is_inside_obsidian`: имена без
  хвостовых точек и пробелов плюс развёрнутый путь ближайшей папки.
- **`ReplaceFileW` получает путь с `\\?\`** (Р-299): это единственный
  вызов записи мимо std, а std приставку ставит сама.
- **Пакетная правка читает с подсказкой проекта** (`read_raw(bytes,
  hint)`, Р-299) — как редактор при открытии.
- **Удаление — только в корзину**, мер две: `SHQueryRecycleBin` до удаления
  и `FOF_WANTNUKEWARNING` (Р-110).
- **Правка чужих файлов пачкой** — переименование со ссылками и замена
  по проекту: список показывается **до** записи (Р-136), план считается
  симуляцией (Р-137), байты сверяются перед каждой правкой, вкладка
  с несохранёнными правками не трогается (Р-138, Р-222), файл читается
  без приведения переносов (`read_raw`), отмена — обратными правками
  (Р-221). Код записи один — `fsx/text_edit`.
- **Живое представление правится, только если в нём лежит именно эта
  вкладка** (Р-105): иначе сохранение запишет в файл чужой текст.
- **Повторное открытие открытого файла только показывает вкладку** —
  ядро отвечает `reused` без текста (Р-296); перечитывание
  (`replaceContent`) раскладку не трогает. Подменить вкладку текстом
  с диска — значит стереть несохранённые правки.
- **«Изменён» — не только текстом** (Р-297): смена кодировки, BOM,
  переносов, исчезнувший файл, своя версия вопреки диску — через
  `markChanged`, признак держится до сохранения. После записи исходным
  становится **записанный** текст (`markSaved`), а не текущий.
  Закрытие многих вкладок — сначала все вопросы, потом закрытие.
- **Автосохранение пишет только то, что можно записать, ни о чём
  не спрашивая** (Р-141); файл, исчезнувший с диска, не пишется.
  Черновики от настройки не зависят.
- **Вид вкладки живёт в ядре**: `text`, `settings`, `image`, `pdf` (Р-180);
  у не-текста нет текстовой части, и это видно типу —
  `Tab.editor: TabEditor | null` (Р-188). Байты картинки и PDF живут,
  пока вкладка на экране (Р-193); пределы 16 и 64 МиБ (Р-196).
- **Один процесс на папку данных** (Р-191): второй экземпляр отдаёт
  аргументы первому и выходит.

### Проекты, дерево, индекс

- **Дерево не обходится целиком** — ни в ядре, ни во фронтенде (Р-054).
  Полный обход — только у индекса.
- **Индекс — кэш** (Р-058…Р-062): чужая схема или порча лечатся
  перестроением. Строка есть у каждого файла, содержимое — у текстовых
  (`has_text`, Р-216); три ключа ссылки — путь, имя целиком, имя без
  расширения (Р-217).
- **Правила игнорирования действуют и на индекс**: скрытое в дереве,
  но находимое поиском, — утечка.
- **Ссылка разрешается при запросе**, а не при записи в индекс.
- **Связи разбираются только у markdown и не внутри кода и формул**
  (Р-069, Р-275): одна проверка `linksLive` + `insideNode(…, CODE_NODES)`
  на подсветку, переход и превью.
- **Строка пользователя не идёт в запрос как есть**: в FTS5 каждое слово —
  в кавычках, в `LIKE` — `_` и `%` экранируются. `lower()` SQLite знает
  только латиницу — нижний регистр считается в Rust отдельной колонкой.
- **Дом для заметок — корень** (Р-236); роль вычисляется по настройке,
  а не хранится в сессии.

### Окно, области, команды, клавиши

- **Дерево областей живёт в ядре** (Р-207); раскладка пишется в сессию,
  только когда областей больше одной — ради отката. `editorView()`
  и `pdfView()` отвечают за активную область, команда не хранит
  представление дольше вызова (Р-208). Зеркала — через главное (Р-209);
  видимое состояние вкладки — `visibleState(tab)`. Фокус области
  назначает щелчок на стадии захвата (Р-210).
- **Полоса вкладок — две части** (Р-301): ряд листается, «+» стоит
  у края вне ряда. Что под указателем на полосе — только
  `elementFromPoint`: при нажатии на вкладку полоса захватывает
  указатель, и цель щелчка — сама полоса. Двойной щелчок по пустому —
  только если **оба** нажатия пришлись на пустое (`ui/tab-strip.ts`):
  иначе двойной щелчок по крестику последней вкладки создаёт файл.
- **Пункт меню не заводит своё действие** — ссылается на команду реестра
  (Р-107); значок принадлежит команде, таблица одна — `icons/commands.ts`,
  полноту сторожит тест (Р-148). Неприменимая команда гаснет, а не исчезает
  (Р-189). Контекстный пункт без команды зовётся `menu.*`.
- **Новые команды — без сочетаний по умолчанию** (Р-127). Клавиша
  называется по положению (`event.code`, Р-121); `defaultKeymap` CodeMirror
  работает мимо нашего реестра, наш диспетчер на перехвате сильнее (Р-122);
  `Tab` — единственное сочетание вне реестра (Р-115); `F2` контекстный
  (Р-117); аккордов нет (Р-123). Буфер обмена на своих клавишах — за вебвью
  (Р-108), чтение буфера — в ядре (Р-109).
- **Захват нажатия — крючок внутри диспетчера**, и он обязан сниматься
  при размонтировании (Р-125): иначе приложение глохнет.
- **В диалоге по умолчанию — безопасный вариант** (Р-093), необратимый
  помечен `danger`. Свой модальный диалог, не системный.
- **Сообщения — одной фразой в полосе** (`notify`, живёт 6 секунд);
  ошибки конфигов — полосой предупреждений, пока их не прочитают.

### Конфиги и откат

- **Терпимое чтение** (Р-248 — настройки, Р-273 — раскладка): всё
  незнакомое называется строкой, всё знакомое применяется; целиком
  отвергаются только сломанный TOML и чужая версия формата. Правка
  из окна проверяется `edit::verify` — «не добавляет жалоб».
- **«Файла нет» и «файл не читается» — разные случаи** (Р-298): свои
  конфиги читать только через `fsx::config::read` — `None` лишь при
  отсутствии файла; нечитаемый не правится и называется. Нечитаемый
  снимок сессии откладывается в `session.unreadable.toml`, черновики
  поднимаются вкладками.
- **Приложение пишет в `settings.toml` только через `toml_edit`**, по одной
  настройке, итог проходит наш разбор до записи (Р-089); новый раздел —
  в конец файла: комментарии под заголовком без ключей принадлежат
  следующему заголовку.
- **Откат на прошлую версию**: прошлые версии уже у людей и строги.
  Новое поле кладётся туда, где прошлая версия его пропустит (у снимка
  раскладки нет `deny_unknown_fields`, у снимка буфера есть); проверять
  разбором, а не рассуждением — тест
  `snapshot_is_readable_by_the_previous_version`. В приёмке — раздел
  «Откат» и строка в заметках выпуска.
- **Образец файла с комментариями кладётся при первом запуске** и никогда
  не перезаписывается.

### Превью markdown

- **Строка под курсором — исходник** (Р-158); единица раскрытия — блок
  (Р-184). Превью прячет и рисует, но не сочиняет слов (Р-178); копируется
  файл, а не экран (Р-160).
- **Прячется знак внутри известного родителя**, а не «узел разметки»
  (Р-168); знак — вместе с одним пробелом (Р-173). У цитаты все пробелы
  за `>` прячутся только прямо в `Blockquote`; в коде и списке дальше —
  отступ (приёмка этапа 17).
- **Украшения пересобираются и когда приезжает разбор** (Р-169):
  `syntaxTree(update.startState) !== syntaxTree(update.state)`.
- **Блочное превью — поле состояния** (Р-203), одно на таблицы, формулы
  и схемы — `editor/block-preview.ts`. Замену через границу строк
  от плагина CodeMirror молча не принимает — **тесты это не ловят**.
  Строки и клетки поля после правки пересобираются только на задетом
  отрезке (Р-294); что зависит от курсора — среди замен, полным
  проходом. Сдвиг против сборки с нуля сверяет тест правками вразброс.
- **Разбор один на редактор и вывод** — `editor/markdown-language.ts`
  (выделение, frontmatter, формулы, сноски, комментарии `%%`). Расширение, которое смотрит дальше
  следующей строки, инкрементальный разбор ломает молча: незакрытое
  тянется до конца файла, проверка — тест «правка с кусками прошлого
  дерева против разбора с нуля» (`TreeFragment.applyChanges`, текст
  длиннее 128 знаков).
- **Щелчок по задаче — единственное место превью, меняющее текст** (Р-231).
- **Свойства** (Р-291) — карточкой в поле блочного превью, **только
  показ**: разбор узкий (`editor/properties.ts`), всё непонятное —
  исходником целиком, незакрытый frontmatter — тоже. Своих слов нет
  (Р-178): ни «Свойства», ни «Добавить свойство», дата как записана.
- **Поле ввода внутри виджета CodeMirror — `textarea`/`input`, не
  `contenteditable`** (Р-292): корню виджета CodeMirror ставит
  `contenteditable="false"`, а вложенная область правки делит выделение
  с текстом — `Ctrl+A` выделял всю заметку. Блочному виджету поле
  строки (`padding-left` у `.cm-line`) не достаётся — `space-line-start`.
- **Шрифт заметки** (Р-285, Р-290): свои токены `font-family-note`/
  `font-size-note`, по умолчанию Segoe UI 16 px во всех темах, человек —
  `[font.note]`; за `[font.editor]` не едут. Код в заметке — шрифтом
  редактора через `zn-mono` и `zn-code-block`, долей `font-size-note-code`.
- **Карточка коллаута** (Р-287) — в поле блочного превью
  (`blockShapes`), не в плагине: строки меняют высоту, клетки поля
  получают те же поля. Подложка — `rgba` из ядра (`color-callout-*-tint`),
  не `color-mix`: Word его не поймёт. Непрозрачное внутри строки прячет
  выделение — либо полупрозрачно, либо выделение куском поверх
  (`cardSelection`). Фон у строки не гасить прозрачным: он перебивает
  подложку карточки (`quietActiveLine`).
- **Поле слева пусто** (Р-284): стрелка свёртки — только у строки под
  указателем (`hoveredLine` в `editor/folding.ts`) и у свёрнутого; черты
  поля нет; в заметке с превью (класс `zn-note`) строка курсора
  не подсвечивается.
- **Сетевые адреса не загружаются никогда** (Р-202), **и сетевые пути
  тоже** (Р-300): `\\сервер\папка` из текста файла или из содержимого
  папки сам по себе не читается — Windows отдала бы серверу хэш пароля.
  Проверка одна — `fsx::network::is_network`; во фронтенде — две косые
  любого вида, до и после раскодирования. По ссылкам в открытой папке
  не ходим: вид — по записи каталога, свои файлы проекта — только
  настоящие (`tree::is_plain_file`).

### Вывод наружу: печать, PDF, HTML, копирование

- **Один обход дерева превью** (Р-263): рендер `html/markdown.ts`
  синхронный, ресурсы (код, картинки, формулы, схемы) готовит
  `html/convert.ts`, контекст один на всех — `convertContext`

- **Бумага светлая** — светлая тема пары (Р-268); режим печати ставит
  `color-scheme: light`, иначе поле листа при тёмной теме выходит чёрным.
- **Предел вывода — 1 МиБ** (Р-265), схемы — 10 000 знаков (Р-278).
- **Word**: стиль вписывается в элементы; `<del>`, `rgba()` и рамку
  у `<div>` Word не понимает; ровно 12 pt у пунктов списка и блоков
  подменяет на 14 — копирование пишет 12,5 (Р-295); MathML — с `xmlns` и неразрывным пробелом
  за строчной формулой (Р-277); схема — картинкой PNG с фоном подложки
  (Р-279).
- **SVG схемы ставится в документ только через `withUniqueIds`** (Р-281):
  одна готовая строка на экране и на бумаге давала бумаге скрытые
  стрелки и тени. Цвета бумаги — `paperTheme`.
- **Стиль формул — `editor/math-style.ts`**, шрифт Temml не поставляется
  (Р-280): в нём запрет коммерческого использования.

- **Разметку с наведением проверять в состоянии наведения**: кнопки окна

## Стек

Tauri v2 · Rust · TypeScript + Svelte 5 · CodeMirror 6 · **Lezer** (подсветка,
этап 2) · SQLite FTS5 через `rusqlite` (этап 2) · `notify` (задача 10) ·
`ignore` (задача 9) · **pdf.js** (`pdfjs-dist`, задача 71) · **Temml**
(формулы, задача 115) · **mermaid** (схемы, задача 117).

`pdf.js` — единственная крупная зависимость фронтенда и выбор владельца
(Р-181): встроенный просмотрщик WebView2 был бы бесплатен по размеру,
но потребовал бы ослабить политику безопасности окна. Своими руками PDF
не рисуют — это отдельный продукт. Обошёлся почти во весь прирост
установщика за этап — 471 КиБ.

Вся тяжёлая работа — файловый ввод-вывод, кодировки, обход дерева, индексация —
на стороне Rust. Фронтенд занимается отображением и вводом.

**Исключение — подсветка синтаксиса.** Она на Lezer, во фронтенде, и это
осознанно: документ уже живёт там (Р-002), а гонять диапазоны подсветки через
IPC на каждый символ противоречит инварианту 6. Решение Р-042 — там же почему
не Tree-sitter.

TypeScript зафиксирован на 6.x: `svelte-check` не поддерживает 7.x.

## Как писать код

**Про Rust.** Владелец проекта знает Rust слабо и учит его на этом проекте.

- Каждый нетривиальный кусок Rust сопровождать коротким пояснением: почему такой
  тип владения, зачем здесь `Arc`/`Mutex`/канал, что делает эта аннотация времени
  жизни. Если пояснение нужно и через полгода — комментарием в коде, иначе в чате.
- Предпочитать простые и очевидные конструкции сложным и «идиоматичным», если
  разница в производительности не измерима. Читаемость важнее.
- Не разбрасывать `unsafe`, макросы и хитрые обобщённые типы. Любой `unsafe`
  требует отдельного обоснования и записи в журнал решений.
- Если запрос основан на неверном понимании языка — сказать прямо и объяснить,
  как правильно.

**Зависимости.** Перед добавлением любой библиотеки — сначала обосновать, почему
без неё нельзя, и записать обоснование в `DESIGN.md`. Минимум зависимостей,
максимум простого собственного кода там, где библиотека решает лишь малую часть
задачи.

**Никаких заглушек.** Если что-то не реализовано — явная пометка `TODO` и строка
в плане, а не фиктивное поведение, изображающее работу.

## Оформление

Механика оформления — часть архитектуры, а не косметика.

- **Ни одного зашитого цвета, отступа, радиуса, тени или размера шрифта в коде
  компонента.** Только CSS-переменные из слоя токенов. Это проверяется тестом
  `tests/tokens.test.ts` — он ловил нарушения шесть раз, в том числе мои.
  Цвета подсветки синтаксиса — тоже токены (Р-047). Он же сверяет, что каждая
  переменная `--zn-*` объявлена: `var(--zn-опечатка)` молча пуста, свойство
  отбрасывается, и элемент едет на умолчании браузера.
- Тема — файл в папке пользователя, TOML, применяется без перезапуска.
- Светлая и тёмная обе, плюс следование системной. Работает только в одной —
  это дефект токенов.
- Иконки — через реестр по логическим именам (`file.markdown`, `action.save`),
  не вставляются в разметку напрямую.
- Всё настраиваемое живёт в читаемом конфиге, который можно править руками.
  Интерфейс настроек — надстройка над файлом.
- **Гибкость не должна протекать в код компонентов.** Если новая настройка
  требует ветвлений по всему интерфейсу — архитектура выбрана неверно, сказать
  об этом сразу.
- Настраиваемое и красивое — разные задачи. Первая с самого начала, вторая —
  этап полировки. До тех пор базовая тема сдержанная и нейтральная.

Что в оформлении легко нарушить:

- **Три слоя фона** (Р-083): `bg-canvas` — подложка окна и утопленное
  (поле ввода в панели, блок кода), `bg-surface` — панели, `bg-raised` —
  рабочая область, диалоги, всплывающее. Порядок ролей в светлой и тёмной
  теме один.
- **Начертаний три**: `normal` 400, `medium` 500, `strong` 600. **Цветов
  кода шесть** (Р-082) — захотелось седьмой, сначала проверить, точно ли
  роль про язык.
- **Читаемость темы считается, а не оценивается на глаз** (Р-078, Р-143):
  контраст на трёх фонах, цвета подсветки, различимость в CIE Lab;
  проверка одна на тест и редактор тем — `theme/readability.rs`.
- **Размер значка — роль контейнера**, а не свойство значка (Р-096,
  Р-100): `--zn-control-icon-size` переопределяется у контейнера. Знак
  приложения — единственная двухцветная иконка (Р-099). Размер кнопки
  панели — тоже роль (Р-150).
- **Вид панели — класс `panel`**, стиль один, в `AppShell`. Вид файла —
  `icons/files.ts`, одна таблица на значок и цвет. `fonts.css` — только
  `@font-face`.
- **Наше правило для чужого класса повторяет путь чужого правила**
  (задача 100): чужая тема CodeMirror выигрывает весом, а не порядком.
  CodeMirror считает нашу тему светлой — его `&light`-правила действуют
  всегда. Подложки блока кода и коллаута полупрозрачны (`bg-block`) —
  сквозь них видно выделение.
- **Единственная анимация — появление диалога и меню** (Р-095). Углы окна
  прямые, и это решено (Р-086).

Если задача упирает в потолок — сообщить и предложить варианты, а не занижать
планку молча.

## Порядок работы

- Одна задача — один коммит с осмысленным сообщением.
- **После каждого этапа — сжатие контекста.** Перед ним всё, что понадобится
  дальше, должно лежать в `DESIGN.md` и здесь, а не в переписке.
- После каждого шага: что сделано, что осталось, что требует решения владельца.
- Каждое существенное решение — в `DESIGN.md`, журнал решений, в том же коммите.
- Тесты обязательны для всего, что касается файлового ввода-вывода, кодировок и
  сессии. Для интерфейса — по обстоятельствам.

## Особенности окружения

- **Файлы `.ps1` сохранять с BOM (UTF-8 with BOM).** Windows PowerShell 5.1
  читает скрипты без BOM как ANSI, и кириллица в них ломает разбор.
- **`Get-Content` для файлов, записанных из Rust, — только с `-Encoding UTF8`.**
  Иначе PS 5.1 прочитает UTF-8 без BOM как ANSI.
- Сборка релиза идёт минутами (`lto = true`, `codegen-units = 1`) — запускать
  фоном, а не блокировать сессию.
- **`src-tauri/target/debug` растёт до десятков гигабайт** (2026-09-06 он был
  44 ГиБ при 3 ГиБ всего остального). Чистится безопасно: всё внутри
  пересобирается, а `target/debug/data` — данные отладочного запуска, их
  стоит оставить. Цена очистки — одна полная пересборка отладочной сборки.
- **Тёплый старт меряется, когда другого окна ZeroNote нет ни одного.**
  Живой сосед держит среду WebView2 тёплой и занижает число на четверть:
  та же сборка дала 422 мс без соседа и 292 мс с ним (приёмка этапа 9).
  С задачи 69 сосед **с той же папкой данных** замер не искажает, а срывает:
  второй экземпляр отдаёт свои аргументы первому и выходит, отчёта не будет
  вовсе. Отладочная сборка и установленная держат разные папки и друг другу
  по-прежнему не мешают.
  Там же второе: замер восстанавливает сессию из папки данных выпускной
  сборки, и её содержимое на число влияет — сессию для замера надо задавать.
- **`std::env::temp_dir()` бывает коротким именем.** На машине непрерывной
  сборки это `C:\Users\RUNNER~1\AppData\Local\Temp`, и путь оттуда — другая
  запись той же папки, чем та, что хранит приложение после `root::normalize`.
  Тесты, сравнивающие пути, обязаны нормализовать (Р-163).
- **Тесты оставляют за собой папки в `%TEMP%`.** Каждый прогон создаёт
  `zeronote-<имя>-<наносекунды>`, и упавший или прерванный тест свою папку
  не убирает. За тринадцать этапов их накопилось 7876 штук на 770 МиБ.
  Чистятся безопасно по шаблону имени. Показательная папка снимков README
  теперь в репозитории (`docs/screenshots/demo`), а не в `%TEMP%`.
- **`target` вычищен 2026-09-25 по просьбе владельца** (проект весил
  почти 18 ГиБ: `target/debug` 12, `target/release` 3,2) — удалено всё,
  кроме `target/debug/data`, `target/release/data` и
  `target/release/bundle` (установщики). Чистить так же: папки `deps`,
  `build`, `incremental`, `.fingerprint`, `examples` и исполняемые файлы;
  `cargo clean` не годится — он сносит и данные запусков. Полная
  пересборка отладочной — несколько минут, тестов — около пяти.
  **Ещё раз 2026-09-27**, после выпуска 0.18.0, по той же просьбе:
  `target` был 19 ГиБ (`debug` 17, `release` 1,7), стал 66 МиБ.
  Удалялось `rd /s /q "\\?\…"` — в `deps` пути длиннее предела.
- **После `Write` с кириллицей проверять файл на `U+FFFD`.** На этапе 15
  дважды: знак BOM в начале содержимого `.ps1` превратил весь файл
  в «кракозябры», а в длинном тексте решения одна буква стала двумя знаками замены.
  Проверка — однострочник на Python: `'\ufffd' in text`. BOM
  в `.ps1` ставить не знаком в тексте, а записью с `utf-8-sig`.
- **Python на Windows пишет текстовый файл с CRLF**, а репозиторий
  хранит файлы байт в байт (`* -text`), почти все — с LF. Файл,
  записанный `open(p, 'w')`, в diff выходит переписанным целиком —
  так на задаче 122 ушло девять файлов, а в коммит задачи 121 —
  `tests/folding.test.ts` (поправлен до отправки). Читать и писать
  только с `newline=''`; проверка — `git diff --stat` перед коммитом:
  число строк правки должно быть похоже на правку. Починка —
  `obs/eol.py <ревизия> <файлы>` в черновиках.
- **Нажатия в ZeroNote — только `bench/ui/keys.ps1`** (с `ZERONOTE_PID`,
  `-At` и всеми нажатиями одним вызовом). Свой `obs/win-input.ps1 -Action
  keys` для этого не годится: на задаче 125 `^p` не дошло, а `>html`
  напечаталось в заметку из хранилища Obsidian владельца. Файл уцелел —
  в отладочных настройках `autosave = false`, — правка снята кнопкой
  «Отменить». После любого сбоя ввода смотреть точку несохранённого
  на вкладке и сверять хэш файла; **автосохранение в отладочных
  настройках не включать**, пока открыты чужие заметки.
- **Закрывать отладочную сборку — только по пути, а не по имени**:
  `taskkill /IM zeronote.exe` закроет и установленную копию владельца.
  Перезапуск отладочной вместе с vite — `obs/restart-dev.sh`.
- **Питон-патчи писать файлом в блокнот, а не heredoc-ом в bash.**
  Через `<<'PY'` последовательность `\n` внутри строк доезжает настоящим
  переносом, и в исходник попадает разорванный литерал: на этапе 13 так
  дважды сломались файлы тестов. Надёжно — `Write` в файл скрипта и запуск
  его по пути. **И не только питон**: на задаче 107 `cat <<'EOF'`
  превратил `\\` в `\` в регулярном выражении и в путях теста. Код
  с обратной косой — только через `Write` или `Edit`.
- **`\u0020` в тексте для `Write` доезжает самим знаком** — как
  `\u00a0`: в регулярное выражение задачи 108 так попал голый
  пробел. Для ASCII писать `\x20` — она доезжает как есть.
- **Запись `\u00a0` в тексте, который пишется инструментом, доезжает
  самим знаком** — и через heredoc, и через `Write`. На этапе 15 так
  в исходник и в этот файл попал невидимый неразрывный пробел вместо
  записи, и тест, сравнивающий строки, стал непонятен глазу. Надёжно —
  собирать строку в скрипте из кода знака (`chr(0x5C) + 'u00a0'`)
  и после записи проверять файл на `chr(0xA0)`.
- **Знак NUL в исходнике делает файл для git двоичным**: `git diff`
  и `git log -p` его правок не показывают, `grep` отвечает «Binary
  file matches». Так с этапов 6 и 3 жили `KeysScreen.svelte`
  и `NoticeStrip.svelte` — разделитель в `join('\0')`, видимо,
  доехал самим знаком, как `\u00a0`. Найдено и убрано после
  задачи 114. Проверка — поиск байта `0x00` в текстовых файлах.
- **Пути Windows в python-строках — только `r'...'`.** `'C:\\Users\\...'`
  внутри обычной строки — это `\U`, начало escape-последовательности
  Unicode: скрипт падает с `truncated \UXXXXXXXX escape`, а если такая
  строка всё же доедет до TOML — приложение скажет «too few unicode value
  digits» и объявит файл настроек испорченным. На этапе 14 так дважды.
  В TOML путь писать одинарными кавычками: `vault = 'C:\Users\...'`.
- **`%TEMP%` от тестов чистился 2026-09-10** (770 папок), **2026-09-25**
  (1005 папок, 153 МиБ), **2026-09-26** (541 папка, 119 МиБ) и ещё раз
  **2026-09-26 вечером**, после приёмки этапа 17 (217 папок, 271 МиБ),
  и **2026-09-27**, после выпуска 0.18.0 (825 папок, 167 МиБ, вместе
  с опустевшей `zeronote-demo`), и в тот же день перед задачей 133
  (544 папки, 52 МиБ). Шаблон `zeronote-*`; снимки README
  теперь снимаются с `docs/screenshots/demo`. **С этапа 19 тесты создают
  junction** (`.obsidian` за связью, ссылка в дереве) — чистить через
  `cmd /c rd /s /q "\\?\<папка>"`, а не `rm -rf` из bash: `rd` связь
  снимает, не заходя в её цель.
- **Смотреть на окно от прошлой сборки — самая дорогая ошибка отладки.**
  Второй экземпляр с той же папкой данных не создаёт окна (Р-191): он
  отдаёт аргументы первому и выходит, а на экране остаётся **старое** окно
  со старым фронтендом. Выглядит как «правка не применилась»: ни горячая
  замена, ни пересборка, ни `npm run build` не помогают. Проверять
  `StartTime` процесса перед первым же снимком; перед проверкой —
  `Stop-Process -Name zeronote`.
- **`cargo run --no-default-features` без живого vite окна не создаёт.**
  Процесс живёт, главного окна нет, снимок выходит 16×16. Отладочная
  проверка — только `npm run tauri dev`.
- **Выпускная сборка не соберётся, пока запущена её же копия.** Cargo
  не может перезаписать `target/release/zeronote.exe`, и сборка падает
  на «Отказано в доступе (os error 5)» после нескольких минут работы.
  Живая проверка на выпускной сборке — закрыть окно перед пересборкой.
- **Подписанную сборку запускать из bash, а не из PowerShell.** У ключа нет
  пароля, и Tauri требует, чтобы `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` была
  задана **пустой**; а `$env:VAR = ""` в PowerShell переменную не задаёт,
  а **удаляет**. Сборка при этом идёт до конца, печатает
  «expect a prompt for password» и встаёт насмерть: ввода нет. Порядок выпуска
  в `DESIGN.md`, раздел 20, написан на bash не случайно.
- **`0xFFFFFFFF` в PowerShell 5.1 — это Int32 −1, а не 4294967295.** Отсюда
  `-120 -band 0xFFFFFFFF` даёт −120, а `[uint32](-120)` падает. Падение при
  этом **не видно**: ошибка непрерывающая, цикл идёт дальше, и скрипт бодро
  отчитывается об успехе. Так первая `scroll.ps1` «прокручивала», не прокручивая
  ничего. В скриптах стенда — `$ErrorActionPreference = 'Stop'`.
- **Проверка процессов в PowerShell ломает цепочку `&&`.**
  `Get-Process … -ErrorAction SilentlyContinue` без процессов возвращает
  код 1, и всё после `&&` не выполняется — так однажды молча
  не запустилась выпускная сборка. Проверку ставить отдельной командой
  или через `;`.
- **`crash-test.ps1` оставляет запущенной выпускную сборку** — закрыть её
  перед пересборкой, иначе «Отказано в доступе».
- **Байтовые литералы `b"..."` в Rust принимают только ASCII.** Для кириллицы —
  обычная строка и `.as_bytes()`.
- **`r#"..."#` ломается о `"#` внутри** — а это любой шестнадцатеричный цвет
  в тесте. Использовать `r##"..."##`.

## Ручные проверки в живом приложении

Дважды за этап 1 проверка молча проверяла не то. Правила, выведенные оттуда:

- `SetForegroundWindow` из фонового процесса Windows **блокирует**. Нажатия
  уходят в чужое окно — однажды прямо в проводник. Забирать передний план
  через `AttachThreadInput` и **проверять результат**, а при неудаче падать.
- `SendKeys` считает служебными `+ ^ % ~ ( ) { } [ ]` — их надо оборачивать
  в фигурные скобки, иначе регулярное выражение доедет искалеченным.
- Событие получения фокуса не сработает, если окно и так было активным:
  фокус нужно по-настоящему увести и вернуть.
- Результат правки сверять **по байтам файла**, а не по снимку экрана.
- Для снимка окна надёжнее `PrintWindow` с флагом `PW_RENDERFULLCONTENT`
  (`0x2`): передний план из фонового процесса дают не всегда, а `PrintWindow`
  работает и с неактивным окном. Без флага содержимое WebView2 в снимок
  не попадает — получится пустой прямоугольник.
- **Скрипты стенда лежат в `bench/ui/`** — снимок, нажатия, щелчок, наведение,
  прокрутка. Не писать их заново: там уже учтены все грабли ниже.
  `shot.ps1` берёт путь **позиционно**: `shot.ps1 -Path x.png` кладёт
  снимок файлом с именем `-Path` в текущую папку — на задаче 135 он
  оказался в корне репозитория.
- **Прокрутка — `scroll.ps1`**, и она понадобилась на выкладке 0.10.0: у окна
  параметров содержимое длиннее экрана, кнопка «Обновления» под сгибом,
  а клавишами её не достать — прокручивается вложенная область без фокуса.
  Запасной путь без скрипта — щелчок по дорожке полосы прокрутки
  (`click.ps1 1194 700`), он листает страницами.
- **Системное окно живёт в своих координатах.** Снимок `shot.ps1` даёт
  координаты от угла окна ZeroNote, а диалог обновления — отдельное окно
  Windows, и попасть в его кнопку можно только по снимку всего экрана
  и щелчку по абсолютным координатам. Числа из этих двух систем не смешивать:
  на выкладке 0.10.0 они разошлись на 220 пикселей по вертикали, и щелчок
  «по кнопке» уехал в список настроек.
- **Диалог «Сохранить как» из печати — системное окно.** Скрипты стенда
  выводят вперёд главное окно, и ввод уходит мимо. Писать в него —
  щелчком по координатам экрана и `SendKeys` в активное окно; `Ctrl+A`
  в поле имени там не выделяет — `{END}+{HOME}{DEL}`.
- **Координаты дерева съезжают, когда появляется полоса вкладок.** Открыв
  первый файл, все строки уезжают вниз на её высоту — и следующий щелчок
  по «тем же» координатам попадает в соседнюю строку. Я потратил на это
  полтора часа, разыскивая несуществующую регрессию: снимок надо делать
  непосредственно перед щелчком, а не в начале проверки.
- **Сочетание, посланное без `-At`, доезжает не всегда** (задача 86).
  Выглядит это точно так же, как «команда не работает», и уводит в сторону:
  сначала в «сочетание крадёт вебвью», потом в «команда падает». Слать
  сочетания со щелчком; если сомневаешься, доходит ли нажатие вообще —
  открыть вкладку «Клавиши» и нажать там: захват показывает само нажатие.
- **`SendKeys` не вводит кириллицу при английской раскладке системы.**
  Буквы просто не появляются, а скрипт отчитывается «отправлено» — тот же
  вид, что у прошедшей проверки. Латиница идёт всегда. Проверки ввода
  строить на латинских именах либо готовить текст в файле заранее
  и дописывать одну букву (задача 82).
- **`hover.ps1` до 2026-09-25 наводил, не наводя**: `SetCursorPos`
  вебвью о наведении не сообщает, и снимок показывал «подсветки нет».
  Теперь за переносом идёт `mouse_event` с движением на ноль пикселей.
  Заодно: снимок сразу после наведения бывает с остатком прошлого
  наведения — целиться в другую кнопку и сверять, какая горит.
- **`keys.ps1 -At x,y`** щёлкает прицельно, а не в середину окна: в середине
  лежит текст, и щелчок туда двигает курсор.
- **Первое действие после смены переднего плана теряется** — нажатие,
  щелчок или прокрутка. Не чинить приложение по одному снимку — повторить.
- **Палитра — латиницей**: команды вызываются из неё как `>pdf`, `>html`,
  затем **щелчок по пункту** — Enter при палитре с `-NoClick` уходит
  в системное меню окна. Кириллицу стенд не впишет: «Копировать
  с оформлением» — правым щелчком в тексте, «Сведения» — шестерёнкой
  внизу слева и прокруткой параметров.
- **Сообщение о сделанном живёт в полосе 6 секунд** — снимать сразу.
- **Окон ZeroNote бывает два и три** — установленное, выпускное,
  отладочное: скрипты стенда требуют `ZERONOTE_PID`, а закрывать —
  по номеру процесса, чтобы не закрыть копию владельца.
- **Перед щелчком окно прибивается к началу экрана.** Между вызовами оно
  переезжает, и координаты от прошлого положения промахиваются на сотни
  пикселей — при этом скрипт отчитывается об успехе.
- **Переднего плана мало для клавиатуры.** WebView2 держит содержимое
  в дочернем окне, и пока щелчка внутрь не было, фокус остаётся на рамке:
  нажатия приходят в приложение и не доходят до вебвью. Сначала щелчок
  в рабочую область, потом ввод. Проверять на команде, которая точно
  работала раньше (`Ctrl+N`), — иначе будешь чинить приложение вместо стенда.
- Для щелчка передний план всё-таки нужен. Помогает нажать и отпустить `Alt`
  перед `SetForegroundWindow`: Windows отдаёт передний план охотнее, если
  только что был ввод с клавиатуры.
- **Страницу без окна снимает сам Edge** — тем же движком, что WebView2:
  `msedge.exe --headless=new --disable-gpu --hide-scrollbars
  --window-size=W,H --screenshot=<путь.png> file:///<путь.html>`,
  лежит в `C:\Program Files (x86)\Microsoft\Edge\Application`.
  Годится, чтобы увидеть вид HTML — формулы, вывод экспорта — до кода
  в приложении: так на плане этапа 17 сравнивались Temml и KaTeX.
- **`GetWindowRect` шире видимого окна**: в него входит невидимая рамка
  изменения размера. Координаты из снимка и координаты для щелчка расходятся
  на пару десятков пикселей — то есть на строку-другую списка. Целиться надо
  по проверке, а не по вере: щёлкнуть, снять экран, убедиться, что попал.

Общее правило: проверка, которая не может провалиться, выглядит точно так же,
как проверка, которая проходит.

## Структура

```
src/                фронтенд: ipc/ editor/ ui/ theme/ icons/ keymap/ state/ actions/
src-tauri/src/      ядро: commands/ text/ fsx/ model/ project/ tree/ session/
                    settings/ keymap/ theme/
src-tauri/tests/    интеграционные тесты; fixtures/ — 17 эталонных файлов
bench/              perf.ps1 — замеры, crash-test.ps1 — инвариант 4,
                    ui/ — стенд ручных проверок в живом приложении
design/             дизайн-референс этапа 3 и его разбор
icons/              знак приложения: исходники, разбор, сборка .ico;
                    files/ — рисунок и сборка значков типов файлов
```

`commands/` не содержит логики — только маршалинг в `text/`, `fsx/`, `model/`.
Поэтому вся логика тестируется обычным `cargo test` без запуска приложения.

Где что во фронтенде:

- `editor/` — CodeMirror: `markdown-language.ts` (разбор), `live-preview.ts`
  (превью строк), `block-preview.ts` (таблицы, формулы, схемы), `math*.ts`,
  `diagram*.ts`, `frontmatter.ts`, `wikilinks.ts`, `langs.ts` (языки
  по требованию, Р-066);
- `html/` — вывод HTML: `convert.ts`, `markdown.ts`, `code.ts`, `tab.ts`,
  `document.css`; `print/`, `export/` — печать, HTML, PDF, копирование;
- `state/` — состояние окна (`tabs`, `panes`, `settings`, `modal`,
  `notices`); `actions/` — действия команд; `keymap/registry.ts` — команды;
- `scripts/licenses.mjs` — уведомления о сторонних компонентах;
  `bench/diagram` — замер схем и сборки документа.

## Приёмы, устоявшиеся за этап 1

Повторять, а не изобретать заново:

- **Канонический список — в Rust, потребитель — во фронтенде, тест сверяет.**
  Так сделаны токены оформления (`tokens.rs` ↔ `tokens.css`) и команды раскладки
  (`keymap/mod.rs` ↔ `keymap/registry.ts`). Расхождение валит сборку.
- **Конфиги: читаем терпимо, ошибаемся громко.** Отсутствующий ключ берёт
  умолчание; опечатка и негодное значение называются по имени и показываются
  полосой предупреждений, а **остальные значения применяются** (Р-248);
  приложение остаётся работоспособным.
- **Образец файла с комментариями кладём при первом запуске** и никогда не
  перезаписываем существующий.
- **Ошибки пользователю, а не в лог.** Полоса предупреждений вверху окна.
- **Свой модальный диалог** (`state/modal.svelte.ts`): системный умеет два
  ответа, а «отмена» вместо «не сохранять» — это тихая потеря данных.
- **Тяжёлое — с задержкой.** Черновики через 2 с, счётчик совпадений через
  150 мс. Мгновенное остаётся мгновенным.
