# ZeroNote — правила проекта

Краткий свод для рабочих сессий. Подробности — в [DESIGN.md](DESIGN.md).
При расхождении между этим файлом и `DESIGN.md` прав `DESIGN.md`.

## Что это

Десктопный редактор для Windows: скорость развёртывания Notepad++ плюс папки
как проекты и удобства VS Code и Obsidian (Р-114). Один разработчик, работа
по вечерам.
Тестировщики — около 35 друзей-разработчиков. Проект будет опубликован в
открытом доступе.

Формат проекта — **свой** (`zeronote.toml`), а не разбор `.obsidian`; из
хранилища Obsidian переносится один раз пара настроек узким переходником.
Связи между заметками (`[[wikilinks]]`, frontmatter, теги) — свойство
markdown-файлов в проекте, а не «режима Obsidian». Решение Р-022.

## Границы первого круга

Только Windows 10/11, только локальная файловая система.

**Вне области — не реализовывать, не закладывать, не «на всякий случай»:**
синхронизация и облако, Linux, Android, шифрованные контейнеры, менеджер паролей,
плагинный API, макросы, пользовательские синтаксисы (UDL), LSP и автодополнение,
сравнение файлов, FTP/SFTP, совместное редактирование.

Возникла идея из этого списка — не реализовывать, а добавить строку в `DESIGN.md`,
раздел «Отложено».

## Инварианты — нарушать нельзя никогда

1. **Чужие файлы неприкосновенны.** Сохраняются исходная кодировка, тип переноса
   строк, наличие/отсутствие финальной новой строки, содержимое frontmatter.
   Никакого автоформатирования и нормализации без явной команды пользователя.
2. **`.obsidian` только для чтения.** Читать можно. Записывать — нельзя ни при
   каких условиях.
3. **Сохранение атомарное.** Временный файл в той же директории, сброс на диск,
   замена целевого. Права и атрибуты исходного файла сохраняются.
4. **Несохранённые данные не теряются.** Черновики пишутся с задержкой ~2 с после
   последнего изменения. После аварийного завершения восстанавливаются все
   вкладки, включая буферы без файла на диске.
5. **Кодировка — часть модели буфера, а не деталь ввода-вывода.**
6. **Ввод не блокирует отрисовку.** Индексация, обход дерева, поиск по папке —
   в фоне и отменяемы.

Если запрос противоречит инвариантам или границам области — сказать прямо и
предложить альтернативу, не выполнять молча.

**Этап 2 закрыт, метка `v0.2.0`.** Корни и `zeronote.toml`, дерево файлов
со слежением, индекс FTS5, быстрое открытие, поиск по проекту, подсветка
синтаксиса, связи между заметками, переходник Obsidian. Приёмка — `DESIGN.md`,
раздел 13. **Инвариант 6 закрыт полностью**: 3,5 мс на ввод под индексацией
против 3,1 мс в покое.

**Этап 5 идёт** — «каждый день»: контекстное меню по правому щелчку, свёртка
блоков, парные скобки, отступы, невидимые символы, закладки. План и решения —
`DESIGN.md`, раздел 18, Р-106…Р-115.

**Ориентир сменился: VS Code и Obsidian** (Р-114, решение владельца).
От Notepad++ остаётся скорость развёртывания — мгновенный старт и открытие
файла; удобства, оформление и сочетания равняются на VS Code и Obsidian.
Занятые сочетания задним числом не переставляем: у тестировщиков четвёртый
месяц мышечной памяти. Расхождения — списком, отдельной задачей этапа 6.

**Задача 35 сделана**: отступы. Определяются по содержимому файла, настройка
`[editor] indent_style` и `indent_width` — только умолчание (Р-106).
Определённое видно в строке состояния, там же меняется для одной вкладки.

- **Смена отступа не переписывает файл.** Меняется только то, чем набирается
  новый; преобразование уже набранного — отдельная явная команда, которой
  пока нет (инвариант 1).
- **`Tab` — единственное сочетание вне реестра** (Р-115). Вне текста `Tab`
  означает переход по элементам, и отнять его глобально нельзя. До задачи 35
  он вообще не был занят и уводил фокус из редактора.
- **Отступ — свойство вкладки**, как язык: у файла с табами `Tab` даёт таб,
  даже когда в настройках пробелы.

**Задача 34 сделана**: парные скобки. Подсветка пары, переход к паре
(`Ctrl+Alt+B`) и автозакрытие настройкой `[editor] auto_close`, по умолчанию
включённой.

- **В прозе кавычка сама не закрывается** (Р-113): markdown и текст без
  языка закрывают только `(`, `[`, `{`. «Сказал» — не строковый литерал.
  Задано данными языка, а не своим обработчиком ввода.
- **Что подсвечено, к тому и переходим.** Порядок поиска пары взят у подсветки
  CodeMirror, включая «курсор внутри только что набранной пары».
- **`@codemirror/autocomplete` в зависимостях ради `closeBrackets`** (Р-112).
  Автодополнение остаётся вне области; границу стережёт тест
  `tests/brackets.test.ts`, а не память.

**Задача 33 сделана**: свёртка блоков. Всё пришло из разбора языка — своих
правил вида «скобка открывает блок» нет ни одного, заголовки markdown
сворачиваются до следующего того же уровня. Поле свёртки справа от номеров
строк, значок — уголок из дерева.

- **Alt с цифрой на дополнительной клавиатуре сочетанием не считается**
  (Р-111). `Alt+0151` — это тире, а не начало `Alt+0`. Цифра верхнего ряда
  сочетанием остаётся: Windows эти клавиши различает, и мы теперь тоже.
- **Свёртки нет у языков из `legacy-modes`** (TOML, YAML, INI, SQL, Shell,
  PowerShell, Lua) и у обычного текста: разбор там построчный, дерева нет.
  Свёртка по отступам — в «Отложено».
- **`SendKeys` шлёт нажатия без скан-кода**, и от этого пуст `event.code`,
  на котором держится вся раскладка. Две проверки подряд выглядели дефектами
  приложения — виноват был стенд. Сочетания слать только через
  `keys.ps1 -Chord "ctrl+shift+p"`.
- **Меню закрывается от любой клавиши**, а не только от Escape.
- **Удаление файлов в дереве будет, но только в корзину** (Р-110, решение
  владельца, задача 38). `SHFileOperationW` с флагом «в корзину» удаляет
  мимо неё молча, когда корзины нет (сетевой диск) или файл не помещается:
  правильный ответ там — отказ с объяснением, а не удаление насовсем.
- **Окон ZeroNote при отладке два** — установленное и `target\debug`.
  Скрипты стенда теперь требуют `ZERONOTE_PID`, если находят больше одного.
  И после перемещения окна первый щелчок приходит в вебвью с координатами
  от прежнего места: полтора часа задачи 32 ушли на «ошибку в расчёте
  положения меню», которой не было.

**Задача 32 сделана**: меню вебвью снято во всём окне, своё меню есть
в редакторе, на вкладке, в дереве (файл, папка, корень, пустое место)
и в поле ввода. Пункты — из реестра команд, сочетания настоящие. Добавились
«копировать путь», «копировать имя», «показать в проводнике», «закрыть
другие».

Что из этого стоит помнить:

- **Буфер обмена на своих клавишах остаётся за вебвью** (Р-108). `Ctrl+X`,
  `Ctrl+C`, `Ctrl+V` до наших обработчиков не доходят: CodeMirror умеет
  построчное копирование и раздачу строк по курсорам, и подражание вышло бы
  хуже. Команды в реестре есть — ради меню и палитры; сверяется пара
  «команда — сочетание», поэтому переназначение работает, а подпись в меню
  не врёт.
- **Чтение буфера обмена — в ядре** (Р-109). `navigator.clipboard.readText()`
  в нашем WebView2 не отвечает вовсе: обещание не разрешается и не
  отвергается. Ветка ошибки никогда не срабатывает, «Вставить» молча ничего
  не делает. Запись при этом браузерная и работает. Это **второй `unsafe`
  в проекте** — `src-tauri/src/clipboard.rs`.
- **Правый щелчок по вкладке сначала делает её активной.** Иначе
  «Сохранить» из меню третьей вкладки сохранило бы первую.
- **Контекстный пункт действует на то, по чему щёлкнули**, и команды
  в реестре у него нет — у клавиши нет объекта под курсором. Такие пункты
  зовутся `menu.*`, а не `file.*`.
- **Меню рисуется в `AppShell`**, а не там, где вызвано: внутри боковой
  панели оно уезжало бы с прокруткой и обрезалось бы по краю.

Два правила этапа, записанные заранее:

- **Отступ определяется по файлу, настройка — только умолчание** (Р-106).
  Настройка «два пробела», применённая к чужому файлу с табами, смешала бы
  одно с другим первым же нажатием `Tab`. То же правило, что у кодировки
  и переноса строк: файл диктует, настройка подсказывает.
- **Пункт меню не заводит своё действие** (Р-107). Он ссылается на команду
  из реестра `keymap/` и оттуда же берёт подпись сочетания. Иначе меню
  и клавиши разъедутся, и заметить это можно будет только глазами.

Публикация в открытый доступ снова отложена: пока в редакторе не хватает
вещей, которые чужой человек заметит на первом часу, показывать его рано.

Показатели не просели: тёплый старт 373 мс, ввод под индексацией 3,7 мс —

**Стенд инварианта 6 теперь идёт тем же путём, что пользователь** (задача 30).
Первой строкой оставлен прежний путь мимо приложения — как база: разница
и есть цена обвязки, около 0,4 мс. Переделка сразу нашла дефект, который
ручные проверки не находили с этапа 1 (Р-105).

**Живое представление правится, только если в нём лежит именно эта вкладка**
(Р-105). Условия «вкладка активна» мало: у буфера без языка подстановка языка
не содержит `await` и выполняется синхронно, когда в представлении ещё прошлая
вкладка. Присваивание её состояния новой вкладке теряло содержимое, а путь
оставался свой — то есть сохранение записало бы в файл чужой текст.

**Где создаётся заметка по ссылке — решают правила разрешения ссылки**
(Р-098, Р-104), а не удобство: косая черта в цели означает путь от корня,
её отсутствие — рядом с ссылающейся заметкой. Иначе файл создался бы не там,
где его потом ищет та же ссылка. Цель с `..`, запретным знаком в имени или
внутри `.obsidian` отвергается с внятным сообщением.

**Оформление блоков кода едет вместе с разбором markdown**, а не в общем наборе
расширений (`langs.ts`): в файле `.rs` весь текст и так код. Подпись показывает
не написанное в ограждении, а то, чем мы язык признали, — и говорит «нет
подсветки», когда не признали (Р-103). Обходятся только видимые строки: блок
бывает длиной в файл.

**Стенд инварианта 6 печатает в свой `EditorView`, а не во вкладку** (Р-102).
Значит, строка состояния в измерение не попадает — и вывод приёмки этапа 3
о цене счётчика курсоров был получен на пути, где счётчика не было. Сейчас
работа строки состояния меряется отдельной колонкой; переделка стенда на
настоящую вкладку — в «Отложено». Всё, что кладётся в строку состояния, лежит
на пути ввода: проверять цену, а не предполагать.

**Столбец считается в единицах UTF-16** (Р-101). Это постоянное время; честный
подсчёт символов означал бы просмотр начала строки на каждое нажатие, а такие
файлы — минифицированные, в одну строку на мегабайты — открывают именно
в редакторе этого класса.

**Размер значка значок себе не назначает** (Р-096, Р-100). Он наследует
`--zn-control-icon-size`, как наследует цвет через `currentColor`; умолчание —
строка списка, а контекст с другой ролью переопределяет переменную у себя:

```css
.button { --zn-control-icon-size: var(--zn-control-icon-size-window); }
```

Ролей пять: окно 10, плитка 20 (боковая полоса и карточка параметров),
знак 20 и 32, строка 16. У значка нет и не должно быть свойства «размер»:
точек вызова тридцать четыре, контейнеров с ролью — пять.

**Знак приложения — единственная двухцветная иконка** (Р-099). Ему разрешён
акцент и только токеном; всем прочим — по-прежнему `currentColor`. Список
исключений держит тест, а не договорённость.

Показатели не просели: тёплый старт 398 мс, ввод под индексацией 3,4 мс.
Обновление поверх 0.2.0 проверено на живой установке: `settings.toml`

Главное правило этапа: **референс адаптируется, а не копируется** (Р-074).
Где он расходится с моделью, побеждает модель: вкладки остаются документами,
графа связей не будет, окно без внешнего поля.

Что легко нарушить в оформлении:

- **Читаемость темы считается, а не оценивается на глаз** (Р-078, Р-079).
  Тест `builtin_themes_are_readable` меряет контраст по WCAG на обоих фонах —
  рабочей области и панели. При первом прогоне он поймал три цвета, которые
  я до того посчитал верными. Новая тема — прогнать тест.
- **Цветов кода в палитре шесть** (Р-082). Операторы, знаки препинания
  и заголовки markdown берут цвет из общего текста. Захотелось седьмой —
  сначала проверить, точно ли роль про язык.
- **Начертаний три**: `normal` 400, `medium` 500, `strong` 600. До задачи 17
  `medium` означал 600, и старые вызовы переведены на `strong`.
- **`fonts.css` выведен из-под проверки на литералы**, но тест следит, что
  в нём нет ничего, кроме `@font-face`. Не класть туда оформление.
- **Три слоя фона, и путать их нельзя** (Р-083, он же уточняет Р-080).
  `bg-canvas` — подложка окна, видна только в зазорах; `bg-surface` — панели;
  `bg-raised` — рабочая область, диалоги, всплывающие. Поле ввода внутри панели
  берёт `bg-canvas`: оно утоплено, а не приподнято. В светлой теме подложка
  темнее панелей, в тёмной — светлее; порядок ролей от этого не меняется.
- **Вид панели задаёт класс `panel`**, стиль для него один — в `AppShell`
  через `:global`. Не повторять скругление и рамку в каждом компоненте.
- **Вид файла — `icons/files.ts`**, одна таблица расширений на значок и на цвет
  (`color-file-*`). Второй такой таблицы заводить не надо: я уже завёл и убрал.
- **Углы окна прямые, и это решено** (Р-086). `DwmSetWindowAttribute` возвращает
  успех и не делает ничего — у окна без обрамления нет рамки для скругления.
  Не переоткрывать без готовности делать окно прозрачным.
- **Строка пользователя не идёт и в `LIKE`.** `_` и `%` там служебные, и запрос
  `план_б` без экранирования находит `планаб`. Ошибка тише, чем со скобкой
  в FTS5: запрос не падает, а молча возвращает лишнее.
- **Режим палитры задаёт точка входа, а не остаток прошлого раза.** `Ctrl+P`
  всегда файлы, `Ctrl+Shift+P` всегда команды; набранное сохраняется.
- **Приложение теперь пишет в `settings.toml`** (Р-089 отменяет ограничение
  Р-013). Только через `settings/edit.rs` на `toml_edit`, только по одной
  настройке, и итог обязан пройти наш `settings::parse` до записи. Испорченный
  файл не переписывается вовсе.
- **Окно параметров показывает наши ключи**, а не список из референса: там
  автосохранение и превью markdown, которых у нас нет. Настройка, которой
  не существует, — это обещание, которое некому выполнить.
- **`bench/ui/keys.ps1 -NoClick`** — если открыта палитра, модалка или список
  выбора. Обычный вызов сначала щёлкает в рабочую область и тем самым их
  закрывает. Координаты щелчка — только именованным `-At "x,y"`: без этого
  первое нажатие уезжало в координаты, а скрипт всё равно отчитывался
  «отправлено».
- **История недавнего — свой файл `data/recent.toml`** (Р-090), не поле сессии.
  Пишется только на явное открытие; восстановление сессии в неё не попадает.
- **Сочетания в интерфейсе берутся из раскладки**, а не пишутся в разметку:
  стартовый экран и палитра показывают то, что и правда нажимается.
- **`Ctrl+D` — мультикурсор, дублирование строки на `Ctrl+Shift+D`** (Р-091).
  Единственное расхождение с раскладкой Notepad++, сделано по решению владельца.
- **Перенос строк — настройка `[editor] wrap`**, общая, не по вкладке (Р-092).
  Применяется отсеком CodeMirror: пересоздание состояний стёрло бы историю
  отмены во всех файлах разом.
- **В диалоге по умолчанию всегда безопасный вариант** (Р-093). Необратимый
  помечается `danger: true` и виден цветом. Enter не должен стирать данные.
- **Полоса предупреждений скрывается по набору сообщений**, а не насовсем
  (Р-094): новая жалоба возвращает её.
- **Единственная анимация — появление диалога и меню** (Р-095). Смещение
  из токена отступов, длительность и кривая — из токенов движения.

Правила по проектам, дереву и индексу, которые легко нарушить не подумав:

- **В папку пользователя не пишется ничего** без явной команды (Р-049).
  `zeronote.toml` создаётся только по кнопке и с переспросом.
- **Настройки проекта не назначают кодировку, а только подсказывают**
  (Р-050…Р-052 рядом). `default_encoding` подменяет догадку определителя
  и никогда — метку порядка байтов или годный UTF-8.
- **Дерево не обходится целиком — ни в ядре, ни во фронтенде** (Р-054).
  Раскрыли папку — прочитали её, и только её. Полный обход есть только
  у индекса: это другой потребитель с другими требованиями.
- **Индекс — кэш, а не данные пользователя** (Р-058…Р-062). Чужая версия
  схемы, испорченный файл, потеря последних записей — всё это лечится
  перестроением, а не миграцией и не сообщением об ошибке.
- **Правила игнорирования действуют и на индекс.** Файл, скрытый в дереве,
  но находимый поиском, — утечка, а не удобство.
- **Языки подсветки грузятся по требованию** (Р-066). Добавляя язык, класть
  его в реестр `editor/langs.ts` через `import()` внутри загрузчика, а не
  обычным импортом: иначе парсер уедет в стартовый пакет.
- **Цвета подсветки — токены, роли общие для всех языков** (Р-047, Р-067).
  Стиль ссылается на CSS-переменные, поэтому смена темы работает без
  пересборки. Проверять обе темы: работает только в одной — дефект токенов.
- **Переходник Obsidian только читает `.obsidian`** и переносит одну
  настройку — фильтры исключения (Р-071). Ключ, который ничего не делает,
  в наш формат не заводим, даже «на будущее».
- **Связи разбираются только у markdown, и не внутри кода** (Р-069).
  `#include` в блоке C++ — не тег, `[[i]]` в примере — не ссылка.
- **Ссылка разрешается при запросе, а не при записи в индекс.** Заметка могла
  появиться позже ссылки на неё; при разрешении на записи такая ссылка
  осталась бы висячей навсегда.
- **`lower()` в SQLite умеет только латиницу.** Путь с кириллицей ею
  не найдётся — приведение к нижнему регистру считаем в Rust и храним
  отдельной колонкой.
- **Строка пользователя не идёт в запрос FTS5 как есть.** Скобка в поисковой
  строке — синтаксическая ошибка запроса, а не поиск скобки. Оборачиваем
  каждое слово в кавычки.

## Стек

Tauri v2 · Rust · TypeScript + Svelte 5 · CodeMirror 6 · **Lezer** (подсветка,
этап 2) · SQLite FTS5 через `rusqlite` (этап 2) · `notify` (задача 10) ·
`ignore` (задача 9) · `notify` (задача 10).

Вся тяжёлая работа — файловый ввод-вывод, кодировки, обход дерева, индексация —
на стороне Rust. Фронтенд занимается отображением и вводом.

**Исключение — подсветка синтаксиса.** Она на Lezer, во фронтенде, и это
осознанно: документ уже живёт там (Р-002), а гонять диапазоны подсветки через
IPC на каждый символ противоречит инварианту 6. Решение Р-042 — там же почему
не Tree-sitter.

TypeScript зафиксирован на 6.x: `svelte-check` не поддерживает 7.x.

## Как писать код

**Про Rust.** Владелец проекта знает Rust слабо и учит его на этом проекте.

- Каждый нетривиальный кусок Rust сопровождать коротким пояснением: почему такой
  тип владения, зачем здесь `Arc`/`Mutex`/канал, что делает эта аннотация времени
  жизни. Если пояснение нужно и через полгода — комментарием в коде, иначе в чате.
- Предпочитать простые и очевидные конструкции сложным и «идиоматичным», если
  разница в производительности не измерима. Читаемость важнее.
- Не разбрасывать `unsafe`, макросы и хитрые обобщённые типы. Любой `unsafe`
  требует отдельного обоснования и записи в журнал решений.
- Если запрос основан на неверном понимании языка — сказать прямо и объяснить,
  как правильно.

**Зависимости.** Перед добавлением любой библиотеки — сначала обосновать, почему
без неё нельзя, и записать обоснование в `DESIGN.md`. Минимум зависимостей,
максимум простого собственного кода там, где библиотека решает лишь малую часть
задачи.

**Никаких заглушек.** Если что-то не реализовано — явная пометка `TODO` и строка
в плане, а не фиктивное поведение, изображающее работу.

## Оформление

Механика оформления — часть архитектуры, а не косметика.

- **Ни одного зашитого цвета, отступа, радиуса, тени или размера шрифта в коде
  компонента.** Только CSS-переменные из слоя токенов. Это проверяется тестом
  `tests/tokens.test.ts` — он ловил нарушения четырежды, в том числе мои.
  Цвета подсветки синтаксиса — тоже токены (Р-047). Он же сверяет, что каждая
  переменная `--zn-*` объявлена: `var(--zn-опечатка)` молча пуста, свойство
  отбрасывается, и элемент едет на умолчании браузера.
- Тема — файл в папке пользователя, TOML, применяется без перезапуска.
- Светлая и тёмная обе, плюс следование системной. Работает только в одной —
  это дефект токенов.
- Иконки — через реестр по логическим именам (`file.markdown`, `action.save`),
  не вставляются в разметку напрямую.
- Всё настраиваемое живёт в читаемом конфиге, который можно править руками.
  Интерфейс настроек — надстройка над файлом.
- **Гибкость не должна протекать в код компонентов.** Если новая настройка
  требует ветвлений по всему интерфейсу — архитектура выбрана неверно, сказать
  об этом сразу.
- Настраиваемое и красивое — разные задачи. Первая с самого начала, вторая —
  этап полировки. До тех пор базовая тема сдержанная и нейтральная.

## Особенности окружения

- **Файлы `.ps1` сохранять с BOM (UTF-8 with BOM).** Windows PowerShell 5.1
  читает скрипты без BOM как ANSI, и кириллица в них ломает разбор.
- **`Get-Content` для файлов, записанных из Rust, — только с `-Encoding UTF8`.**
  Иначе PS 5.1 прочитает UTF-8 без BOM как ANSI.
- Сборка релиза идёт минутами (`lto = true`, `codegen-units = 1`) — запускать
  фоном, а не блокировать сессию.
- **Байтовые литералы `b"..."` в Rust принимают только ASCII.** Для кириллицы —
  обычная строка и `.as_bytes()`.
- **`r#"..."#` ломается о `"#` внутри** — а это любой шестнадцатеричный цвет
  в тесте. Использовать `r##"..."##`.

## Ручные проверки в живом приложении

Дважды за этап 1 проверка молча проверяла не то. Правила, выведенные оттуда:

- `SetForegroundWindow` из фонового процесса Windows **блокирует**. Нажатия
  уходят в чужое окно — однажды прямо в проводник. Забирать передний план
  через `AttachThreadInput` и **проверять результат**, а при неудаче падать.
- `SendKeys` считает служебными `+ ^ % ~ ( ) { } [ ]` — их надо оборачивать
  в фигурные скобки, иначе регулярное выражение доедет искалеченным.
- Событие получения фокуса не сработает, если окно и так было активным:
  фокус нужно по-настоящему увести и вернуть.
- Результат правки сверять **по байтам файла**, а не по снимку экрана.
- Для снимка окна надёжнее `PrintWindow` с флагом `PW_RENDERFULLCONTENT`
  (`0x2`): передний план из фонового процесса дают не всегда, а `PrintWindow`
  работает и с неактивным окном. Без флага содержимое WebView2 в снимок
  не попадает — получится пустой прямоугольник.
- **Скрипты стенда лежат в `bench/ui/`** — снимок, нажатия, щелчок, наведение.
  Не писать их заново: там уже учтены все грабли ниже.
- **Координаты дерева съезжают, когда появляется полоса вкладок.** Открыв
  первый файл, все строки уезжают вниз на её высоту — и следующий щелчок
  по «тем же» координатам попадает в соседнюю строку. Я потратил на это
  полтора часа, разыскивая несуществующую регрессию: снимок надо делать
  непосредственно перед щелчком, а не в начале проверки.
- **`keys.ps1 -At x,y`** щёлкает прицельно, а не в середину окна: в середине
  лежит текст, и щелчок туда двигает курсор.
- **Перед щелчком окно прибивается к началу экрана.** Между вызовами оно
  переезжает, и координаты от прошлого положения промахиваются на сотни
  пикселей — при этом скрипт отчитывается об успехе.
- **Переднего плана мало для клавиатуры.** WebView2 держит содержимое
  в дочернем окне, и пока щелчка внутрь не было, фокус остаётся на рамке:
  нажатия приходят в приложение и не доходят до вебвью. Сначала щелчок
  в рабочую область, потом ввод. Проверять на команде, которая точно
  работала раньше (`Ctrl+N`), — иначе будешь чинить приложение вместо стенда.
- Для щелчка передний план всё-таки нужен. Помогает нажать и отпустить `Alt`
  перед `SetForegroundWindow`: Windows отдаёт передний план охотнее, если
  только что был ввод с клавиатуры.
- **`GetWindowRect` шире видимого окна**: в него входит невидимая рамка
  изменения размера. Координаты из снимка и координаты для щелчка расходятся
  на пару десятков пикселей — то есть на строку-другую списка. Целиться надо
  по проверке, а не по вере: щёлкнуть, снять экран, убедиться, что попал.

Общее правило: проверка, которая не может провалиться, выглядит точно так же,
как проверка, которая проходит.

## Приёмы, устоявшиеся за этап 1

Повторять, а не изобретать заново:

- **Канонический список — в Rust, потребитель — во фронтенде, тест сверяет.**
  Так сделаны токены оформления (`tokens.rs` ↔ `tokens.css`) и команды раскладки
  (`keymap/mod.rs` ↔ `keymap/registry.ts`). Расхождение валит сборку.
- **Конфиги: читаем терпимо, ошибаемся громко.** Отсутствующий ключ берёт
  умолчание; опечатка называется по имени и показывается полосой предупреждений;
  приложение остаётся работоспособным на умолчаниях.
- **Образец файла с комментариями кладём при первом запуске** и никогда не
  перезаписываем существующий.
- **Ошибки пользователю, а не в лог.** Полоса предупреждений вверху окна.
- **Свой модальный диалог** (`state/modal.svelte.ts`): системный умеет два
  ответа, а «отмена» вместо «не сохранять» — это тихая потеря данных.
- **Тяжёлое — с задержкой.** Черновики через 2 с, счётчик совпадений через
  150 мс. Мгновенное остаётся мгновенным.
